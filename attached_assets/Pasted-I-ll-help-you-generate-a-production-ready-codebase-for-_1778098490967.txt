## 🔧 CRITICAL FIXES APPLIED

### DateTime & Timezone Standardization
**Problem (v5.0)**: `Match.kickoff_time` stored without timezone info → ambiguous UTC vs local
**Solution (v6.0)**:
- All timestamps stored as **naive UTC** (`datetime.now(timezone.utc).replace(tzinfo=None)`)
- Explicit UTC assumption on retrieval (`retrieved.replace(tzinfo=timezone.utc)`)
- Alembic migrations handle existing data normalization
- Pattern standardized across all modules

### UUID v4 Standardization
**Problem (v5.0)**: Mixed UUID strings, sequential integers, inconsistent formats
**Solution (v6.0)**:
- All new entities use **UUID v4 string format**
- `id: str = Field(default_factory=lambda: str(uuid.uuid4()))`
- Existing integer PKs maintained for backward compatibility
- Consistent 36-character string representation
