# VIT Explorer Deployment Analysis

## 1. Root Cause Analysis
The initial attempts to deploy `vit-explorer` as a Render Static Site failed because Render's automated build environment for mixed monorepos was incorrectly detecting Python metadata (`pyproject.toml`, `requirements.txt`) at the root. This caused the Node.js build process to fail with `RuntimeError: Expected exactly one LICENSE file in cffi distribution, got 0`, as it tried to install Python build dependencies in a restricted static environment.

## 2. Deployment Methods Attempted

### Option A: Static Site (Explicit Root)
- **Result**: ❌ Failed
- **Observation**: Render still attempted to process root-level metadata even when `rootDir` was set, leading to the same CFFI error.

### Option B: Docker Web Service (Monorepo Dockerfile)
- **Result**: ✅ SUCCESS
- **Implementation**:
  - Updated the central `Dockerfile` to include a multi-stage build that compiles the `explorer/` project using Node 20.
  - Updated `main.py` to mount `explorer/dist` at `/explorer` using FastAPI's `StaticFiles`.
  - Service is now served by the robust Python backend which already has all necessary environment variables and database access.

## 3. Deployment Summary
- **Successful Method**: Option B (Dockerized Web Service).
- **Service Name**: `vit-explorer-docker-svc`
- **Public URL**: https://vit-explorer-docker-svc.onrender.com/explorer/
- **Repository Separation**: **NOT NECESSARY**. The monorepo structure is preserved and operational using the unified Docker strategy.

## 4. Recommended Production Deployment
Stick with the Dockerized Web Service. It ensures that the explorer has direct access to the same environment (and potentially internal RPC endpoints) as the rest of the ecosystem while benefiting from the already-hardened multi-stage build process.
